# 앵커 링크로 페이지 안에서 이동하기

## 1. 학습 목적

[과제 PDF](../assignment-requirements.pdf) 3쪽의 '각 섹션으로 이동하는 앵커 링크' 요구사항을 다룬다. 기존 HTML에서 링크와 도착 영역이 어떻게 연결되는지 확인한다.

## 2. 핵심 개념

앵커 링크는 `a` 요소로 만든 링크다. `href` 속성은 이동할 주소를 지정한다. 주소에서 `#` 뒤의 부분을 프래그먼트(fragment, 문서 안의 특정 부분을 가리키는 값)라고 한다.

`href="#about"`을 누르면 브라우저는 현재 문서에서 `id="about"`인 요소를 찾아 그 영역으로 이동한다. `id`는 요소의 고유 식별자이며 한 문서 안에서 중복하지 않는다. `href`에는 `#`을 쓰고, `id` 값에는 쓰지 않는다. 이름의 대소문자도 맞춘다.

이 동작은 브라우저가 제공한다. 별도의 JavaScript 함수나 라이브러리, 클릭 이벤트 처리 코드는 필요하지 않다. 이동에는 링크를 사용하고, 제출 같은 동작에는 버튼을 사용한다.

## 3. 프로젝트 적용

관련 소스: [src/index.html](../../src/index.html)의 내비게이션과 About 영역. 실제 코드의 연결 부분만 발췌하면 다음과 같다.

```html
<a href="#about">소개</a>

<section id="about" aria-labelledby="about-title">
  <h2 id="about-title">소개</h2>
  <!-- 자기소개 내용 -->
</section>
```

여기서 이동 대상은 `about`이다. `about-title`은 제목 요소의 별도 식별자로, 링크 목적지와 구분한다.

| 링크가 있는 곳 | href | 도착 요소 |
| --- | --- | --- |
| 상단 이름, 홈 메뉴 | `#hero` | 인사말 section |
| 소개 메뉴 | `#about` | 자기소개 section |
| 기술 메뉴 | `#skills` | 기술 목록 section |
| 프로젝트 메뉴, 프로젝트 보기 | `#projects` | 프로젝트 section |
| 문의 메뉴, 문의하기 | `#contact` | 문의 section |
| 소셜 링크 메뉴 | `#footer` | footer |

총 아홉 개의 내부 링크가 여섯 영역을 가리킨다. 이번 단계에서는 기존 연결을 검증하며, 부드러운 스크롤 효과는 이후에 구현한다.

## 4. 실행 흐름

1. 입력: 사용자가 '소개' 링크를 클릭하거나 키보드로 선택해 Enter를 누른다.
2. 브라우저가 `href="#about"`을 해석한다.
3. 주소의 프래그먼트가 `#about`으로 바뀌고, 같은 문서에서 `id="about"` 요소로 스크롤한다.
4. 결과: 자기소개 영역이 화면에 나타난다.

페이지 주소 끝에 `#projects`를 붙여 직접 열어도 프로젝트 영역을 가리킬 수 있다. 문서 하단에 가까운 대상은 남은 스크롤 공간이 부족해 화면 맨 위까지 올라오지 않을 수 있다.

## 5. 확인 방법과 결과

실습 절차와 예상 동작:

1. [README의 실행 방법](../../README.md#실행과-확인)에 따라 페이지를 연다.
2. '소개' 메뉴를 클릭한다. 주소 끝이 `#about`으로 바뀌고 소개 영역이 보인다.
3. 페이지를 다시 열고 Tab 키로 '소개' 링크를 선택한 뒤 Enter를 누른다. 클릭과 같은 이동이 일어난다.
4. 다른 메뉴와 Hero의 두 링크도 눌러 표의 도착 영역과 일치하는지 확인한다.
5. 주소 끝의 프래그먼트를 `#projects`로 바꿔 접속하면 프로젝트 영역이 보인다.

2026-09-07 실행 결과: 로컬 HTTP 서버에서 Chromium 153.0.8010.12를 화면 크기 1280×720, JavaScript 비활성화 조건으로 실행했다. Playwright 1.63.0으로 브라우저 입력을 자동화해 다음을 확인했다.

- 내부 링크 아홉 개를 각각 클릭한 뒤 주소의 프래그먼트가 href와 일치하고 대상 요소가 화면 안에 나타났다.
- '소개' 링크에 키보드 초점을 두고 Enter를 누르면 `#about`으로 이동했다.
- `#projects` 주소에 직접 접속하면 프로젝트 영역이 화면에 나타났다.
- 문서의 ID 중복이 없었다.

검증 도구는 임시 디렉터리에 준비했으며 웹사이트의 실행 의존성이 아니다. 위 실습 절차로 동일한 동작을 직접 확인할 수 있다.

## 6. 질문과 추가 확인

추가 확인: `href`의 이름을 바꾼다면 도착 요소의 `id`도 함께 맞춰야 한다. 주소 끝의 값만 바뀌고 원하는 영역으로 이동하지 않을 때는 이 연결부터 확인한다.
