# CSS로 앵커 이동을 부드럽게 만들기

## 1. 학습 목적

[과제 PDF](../assignment-requirements.pdf) 4쪽의 부드러운 섹션 이동을 구현한다. [앵커 링크](002-anchor-links.md)가 정한 목적지까지 이동하는 방식을 CSS로 지정한다.

현재 구현은 `scroll-behavior: smooth`로 부드럽게 이동하는 기능이다. 동작 줄이기 대응은 과제 요구사항에 없어 제거했다. 이 개념의 의미와 도입·제외 이유는 6절에 정리한다.

## 2. 핵심 개념

`scroll-behavior`는 앵커 이동처럼 브라우저가 수행하는 스크롤의 방식을 지정하는 CSS 속성이다. `smooth`는 중간 위치를 거쳐 부드럽게 이동하고, `auto`는 즉시 이동한다. 마우스 휠이나 손가락으로 직접 스크롤하는 속도를 정하는 속성은 아니다.

`:root`에 지정하면 페이지를 표시하는 영역인 뷰포트의 스크롤에 적용된다. HTML에서는 최상위 `html` 요소가 이에 해당한다. 이 속성은 자식 요소에 상속되지 않으며, body에만 지정한 값은 뷰포트로 전달되지 않는다.

## 3. 프로젝트 적용

[src/css/style.css](../../src/css/style.css)의 기존 `:root`에 다음 속성을 추가했다. 발췌에서는 색상·간격 변수 선언을 생략했다.

```css
:root {
  scroll-behavior: smooth;
}
```

[src/index.html](../../src/index.html)의 `href="#projects"`와 `id="projects"` 연결을 사용한다. 스크롤을 위한 JavaScript 함수나 라이브러리는 추가하지 않았다. 브라우저의 앵커 기능을 사용하므로 주소의 프래그먼트, 링크의 키보드 조작과 방문 기록도 유지된다. 프래그먼트는 주소에서 `#` 뒤에 붙는 부분이다.

## 4. 실행 흐름

1. 입력: 내비게이션의 '프로젝트' 링크를 클릭한다. 모바일에서는 먼저 메뉴 버튼을 눌러 링크를 연다.
2. 브라우저가 `href="#projects"`에서 이동할 요소를 찾고 주소 끝을 갱신한다.
3. `smooth`를 적용해 스크롤 위치가 중간 지점들을 거쳐 변한다.
4. 결과: 프로젝트 영역이 화면에 나타난다.

이동 시간과 속도 곡선은 브라우저가 결정한다. 코드에서 시간을 지정하지 않았다. `#projects`가 주소에 표시되는 시점과 스크롤이 끝나는 시점은 다를 수 있다.

## 5. 확인 방법과 결과

### 확인 목적과 방법

과제에서 요구한 부드러운 이동이 보이고, 기존 링크가 같은 목적지로 이동하는지 확인한다. 정지 캡처로는 중간 움직임을 보여 주기 어려워 직접 관찰하고 스크롤 위치 변화를 측정한다.

1. [README의 실행 방법](../../README.md#실행과-확인)에 따라 페이지를 열고 맨 위로 이동한다.
2. 내비게이션 또는 Hero의 '프로젝트' 링크를 누른다. 모바일에서는 먼저 메뉴 버튼을 연다.
3. 소개와 기술 영역을 지나 프로젝트로 이동하는지 확인한다.
4. 주소 끝이 `#projects`이고 프로젝트 영역이 보이는지 확인한다. 다시 비교할 때는 맨 위에서 시작한다. 이미 목적지에 있으면 움직일 거리가 없다.

`smooth`와 `auto`의 차이 자체를 확인하고 싶다면 CSS의 값을 직접 바꾸고 같은 링크를 눌러 볼 수 있다. 비교 후에는 과제에서 요구한 `smooth`로 되돌린다. 현재 구현의 확인에는 동작 줄이기 설정을 변경할 필요가 없다.

### 확인한 결과

동작 줄이기 분기를 제거한 코드로 2026-09-09 로컬 HTTP 서버, Chromium 153.0.8010.12, Playwright 1.63.0, 한글 나눔 글꼴 환경에서 검증했다. 링크 클릭 후 계산된 CSS 값, 프레임별 스크롤 위치와 최종 주소를 관찰했다.

| 화면 크기와 조건 | 확인한 결과 |
| --- | --- |
| 768×600, 일반 선호 | `smooth`, 중간 위치 25회 관찰, 약 776px의 프로젝트 목적지 도착 |
| 375×720, 모바일 메뉴 열림 | `smooth`, 중간 위치 28회 관찰, 약 954px의 프로젝트 목적지 도착 |
| 768×600, 동작 줄이기 선호 재현 | `smooth`, 중간 위치 25회 관찰, 약 776px 도착. `auto`로 바꾸던 분기가 제거됨 |

세 조건 모두 주소 끝은 `#projects`였고 JavaScript 오류는 없었다. 중간 위치의 관찰 횟수는 이 실행의 측정값이며 고정된 애니메이션 길이나 성능 목표가 아니다.

마지막 조건은 이번 코드 제거가 반영됐는지 확인하기 위한 검증이다. 동작 줄이기를 지원한다는 뜻은 아니다. 브라우저 자체 정책에 따른 차이는 있을 수 있으며, 위 결과는 명시한 Chromium 환경에서 확인한 범위다.

## 6. 질문과 추가 확인

### 동작 줄이기는 무엇이고 언제 쓰는가?

동작 줄이기는 운영체제나 브라우저 환경에서 불필요한 화면 움직임을 줄이려는 사용자의 접근성 선호다. 접근성은 서로 다른 사용 조건에서도 콘텐츠와 기능을 이용할 수 있게 하는 것을 뜻한다. 화면이 크게 확대되거나 미끄러지듯 전환되는 효과가 어지럽거나 산만하게 느껴지는 사용자가 이 설정을 사용할 수 있다.

Windows 11에는 접근성의 시각 효과에서 애니메이션 효과를 끄는 설정이 있고, macOS에는 동작 줄이기 설정이 있다. 운영체제에서 제공하는 기능이라는 사실과 실제로 얼마나 많은 사람이 켜는지는 구분해야 한다. 여기서는 사용 비율을 판단하지 않는다.

웹에서는 `prefers-reduced-motion` 미디어 기능으로 이 선호를 확인한다. `reduce`는 움직임을 줄여 달라는 요청이며, `no-preference`는 그런 요청이 감지되지 않은 상태다. 선호를 확인하는 것만으로 모든 애니메이션이 자동으로 제거되지는 않는다. 개발자가 그 조건에서 적용할 CSS를 작성해야 한다.

### 이 프로젝트에서 왜 넣었고, 왜 제거했는가?

프로젝트 링크를 누르면 화면 전체가 아래로 움직인다. 목적지의 내용을 보는 데 중간 이동 애니메이션은 꼭 필요하지 않으므로, 동작 줄이기를 선택한 방문자에게는 즉시 이동하도록 하는 접근성 보완을 처음에 추가했다. 이전 코드는 `@media (prefers-reduced-motion: reduce)` 조건이 맞으면 `scroll-behavior`를 `smooth`에서 `auto`로 바꿨다.

과제 PDF의 요구사항은 부드러운 섹션 이동이며, 동작 줄이기 대응은 포함되지 않는다. 요구사항에 필요한 코드와 개념에 집중하기 위해 이 조건부 규칙을 제거했다. 현재 소스는 이 선호에 따라 이동 방식을 바꾸지 않는다. 과제에서 명시한 이미지의 `alt`와 폼의 `label` 연결은 구현 범위에 포함된다.

### 왜 개발자 도구의 설정을 바꿔 비교했는가?

이전 비교에는 두 목적이 있었다. 하나는 `smooth`와 `auto`의 이동 차이를 보는 것이고, 다른 하나는 사용자 선호가 전달됐을 때 작성한 미디어 쿼리의 조건이 적용되는지 확인하는 것이었다.

값의 차이만 보려면 CSS를 직접 수정하면 된다. 사용자 선호에 따른 분기까지 확인하려면 실제 운영체제 설정을 바꾸거나 개발자 도구로 그 환경을 재현할 수 있다. 개발자 도구의 설정 변경은 유일한 방법이 아니라, 실제 운영체제 설정을 건드리지 않고 조건을 비교하기 위해 선택했던 방법이다.

Command Menu(명령 메뉴)는 개발자 도구의 기능을 이름으로 검색해 실행하는 창이다. `Show Rendering`은 Rendering 패널을 여는 명령이다. 이 패널의 `Emulate CSS media feature prefers-reduced-motion`은 검사 중인 페이지에 전달할 선호를 재현한다. 이렇게 조건을 흉내 내는 것을 에뮬레이션이라고 한다.

이전 코드에서의 흐름은 `Rendering에서 reduce 선택 → 미디어 쿼리 조건 충족 → auto 적용 → 즉시 이동`이었다. 현재는 이 조건부 규칙을 제거했으므로 해당 비교를 현재 기능의 필수 실습으로 안내하지 않는다.

### 목적지가 화면 맨 위에 맞지 않을 수 있는 이유

주소의 `#projects`는 목적지를, `scroll-behavior`는 이동 방식을 정한다. 목적지가 문서 하단에 가까우면 남은 스크롤 공간 때문에 화면 맨 위까지 올라오지 않을 수 있다.
