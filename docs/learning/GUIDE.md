# 포트폴리오 학습자료 작성 기준

이 프로젝트의 학습자료 작성 기준이다. 자료 작성 단계에만 읽으며, 구현·검증 규칙은 [CLAUDE.md](../../CLAUDE.md)를 따른다.

## 작성 범위

- 실제 구현한 개념을 `NNN-concept-name.md`에 한국어로 기록하고 최초 작성 순서로 번호를 정한다. 같은 개념은 기존 문서를 보완한다.
- 분량은 새 개념과 변경 규모에 맞춘다. 환경 확인·작은 보완은 핵심 개념·프로젝트 적용·확인 결과·남은 확인으로 짧게 작성한다. 기존 개념은 링크로 연결한다.
- 필요할 때 학습 목적 → 핵심 개념 → 적용 → 실행 흐름 → 확인 결과 → 질문·추가 확인 → 참고자료 순서를 활용하되 목차를 채우기 위해 내용을 늘리지 않는다.
- 필요한 메서드·라이브러리의 역할과 인자·반환값, 소스 상대경로와 핵심 코드, 작은 입력부터 결과까지를 설명한다. 전문 용어는 처음에 풀어 쓴다.
- 전달받은 코드 위치와 검증 요약을 우선 사용하고 필요한 구간만 추가로 읽는다. 전체 소스·과거 자료·구현 대화·로그를 일괄 탐색하지 않는다.
- 실제 활용한 공식 문서·표준 등 1차 자료를 관련 개념에 연결한다. 버전별 동작 차이는 버전을 명시한다. 대화 원문·확인되지 않은 사용자 경험·형식적인 학습 상태는 넣지 않는다.

- Codex가 전달한 학습 개념과 관련 코드 위치를 바탕으로 설명 순서와 본문을 구성한다. 문단별 뼈대를 별도로 요구하지 않는다.
- DOM 조작·이벤트·비동기 처리에서는 사용자 입력부터 상태 변경과 화면 업데이트까지 실제 코드의 흐름을 설명한다.
- 사용자의 질문으로 드러난 설명 부족은 기존 개념 문서에 예시와 함께 보완한다. 새 개념이 아니면 별도 문서를 만들지 않는다.

## 검증 기록

- 구현·보완 단계에서 확보한 브라우저 검증 근거로 실행 절차·환경·상태 변화·실제 결과·미확인 항목을 기록한다. 자료 작성을 위해 통과한 검증을 반복하지 않는다. 근거가 부족하면 해당 항목만 미확인으로 남기고 Codex에 보고한다.
- 구현 단계에서는 정지 화면을 캡처하지 않는다. 애니메이션 이해에 필요하면 GIF나 영상을 검토하되 필수 산출물로 만들지 않는다.
- 최종 제출용 스크린샷은 제출 단계의 과제 요구사항으로 별도 관리한다. 필요한 시각자료는 `docs/images/screenshots/<개념 문서명>/`에 두고 상대경로·대체 텍스트·설명을 붙이며, 코드와 명령은 이미지로만 제공하지 않는다.

## 갱신 범위

- 개념 문서를 추가하면 `docs/learning/README.md`의 `순서 | 개념 | 적용한 기능 | 문서` 표를 갱신한다. 코드 수정 시 관련 자료도 반영한다.
- 작업 결과는 `docs/progress.md`의 해당 체크박스와 현재 상태에 반영하며, 검토·자료까지 끝난 뒤 최신 기록·다음 작업·갱신일을 마감한다.
- 루트 README는 사용자 요청이 있을 때만 읽기·검토·수정한다.
- Claude Code는 자료의 정확성과 링크를 확인하고 반영 여부를 완료 보고한다. Codex는 학습자료의 본문과 diff를 재검토하지 않는다.
