# 학습 문서 작성 기준

학습 기록을 작성하거나 검토할 때 이 기준을 읽는다. 자료만 읽어도 학습할 수 있도록 필요한 설명을 담되 이번 개념에 집중한다.

## 뼈대 전달 형식

Codex는 학습 문서를 위임할 때 아래 형식으로 뼈대를 전달한다. 본문은 Claude Code가 이 뼈대로 작성한다.

```text
개념: 문서에서 다룰 개념 한 줄
번호: NNN-concept-name
적용한 기능: 이 개념을 어떤 요구사항에 썼는지
코드 위치: 파일과 함수 또는 줄 범위
설명 순서: 항목을 줄 단위로, 각 줄은 한 문단에 대응
검증 계획: 확인할 동작과 확인 방법
검증 결과: 실행 후 명령·환경·실제 결과·미확인 항목을 채운다
주의: 이 개념에서 틀리기 쉬운 지점이나 제외한 범위
```

## 문서 구성

학습 목적 → 핵심 개념 → 프로젝트 적용 → 실행 흐름 → 확인 방법과 결과 → 질문과 추가 확인 → 참고자료 순서로 구성한다. 해당하지 않는 항목은 생략한다.

새 개념의 의미·사용 상황·요구사항에서 필요한 이유, 메서드의 주요 인자·반환값, 관련 소스의 상대경로와 핵심 코드, 작은 입력부터 출력까지의 흐름을 설명한다. 전문 용어는 처음 나올 때 풀어 쓴다. 검증 방법은 목적과 선택 이유를 함께 기록한다.

## 질문에 따른 보완

- 사용자가 이해되지 않는 부분을 질문하면 답변과 함께 기존 개념 문서의 해당 설명·예시를 보완한다.
- 질문과 추가 확인에는 실제 질문의 요지, 확인한 답과 남은 의문만 정리한다. 대화 원문을 복사하거나 질문마다 새 문서를 만들지 않는다.
- 문서 보완도 정확성과 링크를 확인한 뒤 해당 변경만 커밋한다. 개념·적용 기능이 바뀌지 않으면 목록과 README를 형식적으로 수정하지 않는다.

## 표현

- 개념, 코드에 적용한 내용, 실행 방법과 확인한 결과를 중심으로 작성한다. 사용자 학습 여부나 도구 환경의 제약을 설명하는 상투적인 문구는 넣지 않는다.
- 대화를 읽지 않은 독자도 개념의 의미, 사용 상황, 도입 이유와 요구사항의 관계를 알 수 있게 작성한다.
- 구현에서 제외한 개념을 학습 기록에 남길 때는 제외 이유와 현재 적용 여부를 명시한다.
- 실제로 읽고 활용한 참고자료만 개념 설명과 구현의 근거로 기재한다.

## 검증 기록

- 결과가 없는 항목은 실습 절차와 예상 동작으로 설명한다. 사용자의 경험이나 검증 성공을 만들어내지 않는다.
- 사용자만 확인할 수 있는 실습은 구체적인 절차와 확인 사항을 안내하고 받은 결과를 문서에 반영한다.
- 화면·실행 결과 확인에는 사용 가능한 도구를 활용하고, 필요하면 권한 범위 안에서 설치해 검증한다. 스크린샷은 실제 실행 화면을 캡처하고 기능과 확인 사항을 함께 기록한다.
- 정확성·재현성에 영향을 주는 미해결 문제는 사용자에게 알린다. 공개 문서에는 독자가 알아야 할 실제 기능 제약을 구체적으로 기록한다.

## 갱신 범위

문서를 추가하면 함께 갱신한다.

- `docs/learning/README.md`의 목록 표
- 루트 `README.md`의 학습 기록 링크
- `docs/progress.md`의 현재 상태 블록
