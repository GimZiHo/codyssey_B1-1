## 선택 과제 — PDF 6~7쪽

남은 항목은 2026-09-22에 학습 효과·변경 범위·외부 의존성으로 비교했다. 기존 `applyTheme`과 로컬 저장 흐름에 상태 우선순위를 더할 수 있고 외부 서비스가 필요 없는 시스템 테마 감지를 다음 작업으로 정했다. Hero 타이핑 효과는 표현 중심이라 그 뒤로 두고, 실제 폼 전송은 서비스 계정·전송 데이터·실패 처리 정책을 정한 뒤 검토한다.

- [x] `filter`를 활용한 언어별 프로젝트 필터링. `filterRepositoriesByLanguage`가 원본 `repositories`는 바꾸지 않고 선택한 언어로 거른 새 배열만 그린다. 정식 Google Chrome 153.0.8010.52에서 375·768·1280px 시나리오 105건과 기존 회귀 210건 모두 통과했다([022](learning/022-array-filter-language.md)).
- [x] `prefers-color-scheme`을 이용한 시스템 테마 감지. 저장된 유효한 사용자 선택을 우선하고, 없을 때만 `matchMedia('(prefers-color-scheme: dark)')`로 초기값과 `change` 이벤트 반영을 결정한다. Playwright 1.63.0·Chromium 153.0.8010.12 headless shell로 시나리오 6건 통과했다([023](learning/023-prefers-color-scheme.md)).

## 단계별 진행 순서

아래 항목은 전체 진행 순서이며 한 번의 대화에서 완료할 작업량을 뜻하지 않는다. 2단계부터 시맨틱 HTML, 앵커 링크, 외부 파일 연결처럼 개념별로 나누어 구현·검증하고 학습자료를 작성한다.

1. 요구사항과 작업 기준 정리: 이 문서를 작성하고 PDF와 대조한다.
2. HTML 뼈대와 개발 환경: 여섯 섹션, 앵커 링크, 외부 파일 연결을 만들고 Live Server에서 확인한다.
3. 반응형 CSS: 모바일부터 시작해 태블릿·데스크톱 배치와 테마 변수를 구현한다.
4. 기본 인터랙션: 메뉴, 스크롤, 테마 저장과 애니메이션을 하나씩 구현한다.
5. 폼 검증: 입력 상태와 오류·성공 메시지를 연결한다.
6. GitHub API: 로딩·성공·에러·빈 상태와 재시도를 구현한다.
7. 최종 검증과 제출 준비: 기능을 점검하고 배포, 스크린샷, README를 완성한다.
