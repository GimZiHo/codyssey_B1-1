# 진행 상태와 요구사항 체크리스트

체크박스는 구현하고 검증한 뒤 완료로 표시한다. 선택 과제는 필수 기능 완료 후 검토한다.

## 현재 상태

작업을 시작할 때 이 블록만 읽으면 어디까지 했는지 알 수 있게 유지한다.

- **완료**: 요구사항 정리, HTML 기본 구조·반응형 배치, 메뉴 토글, 앵커 부드러운 이동, 맨 위로 버튼(300px), 내비 배경 전환(60px), 테마 저장·복원, Intersection Observer 등장 효과(20%)
- **남은 기초 항목**: Live Server 환경 확인, 실제 자기소개·프로필, 버튼·카드 hover·transition·box-shadow
- **진행 중**: 없음
- **다음 작업 단위**: 버튼·카드 hover·transition·box-shadow(2절)
- **그 다음**: 폼 검증(4장) → GitHub API 연동(5장) → 최종 검증·배포·README(6장)
- **보류된 결정**: 없음
- **최신 학습 기록**: [Intersection Observer 섹션 등장 효과](learning/014-intersection-observer.md)
- **마지막 갱신**: 2026-09-13

## 1. 개발 환경과 HTML 구조 — PDF 2~3쪽

- [ ] VS Code와 Live Server로 개발 환경을 구성한다.
- [x] HTML, 외부 CSS, 외부 JavaScript, 이미지를 역할별로 분리하고 올바르게 연결한다. JavaScript에는 `defer`를 사용한다.
- [x] `header`, `nav`, `main`, `section`, `article`, `footer`를 의미에 맞게 사용한다.
- [x] Hero에 인사말과 CTA 버튼을 배치한다.
- [ ] About에 자기소개와 프로필 이미지를 배치한다.
- [x] Skills에 기술 스택 목록을 배치한다.
- [ ] Projects에 GitHub API로 가져온 저장소 카드를 표시한다.
- [x] Contact에 문의 폼을 배치한다.
- [x] Footer에 저작권과 소셜 링크를 배치한다.
- [x] 내비게이션에 각 섹션으로 이동하는 앵커 링크를 둔다.
- [x] 모든 이미지에 의미 있는 `alt`를 지정하고 폼의 `label`과 입력 요소를 `for`–`id`로 연결한다.

## 2. 스타일과 반응형 레이아웃 — PDF 3~4쪽

- [x] `css/style.css`를 사용하고 `:root`에 색상, 폰트, 간격 변수를 정의한다.
- [x] `[data-theme="dark"]`에 다크 모드 변수를 정의한다.
- [x] 내비게이션은 Flexbox로 로고를 왼쪽, 메뉴를 오른쪽에 배치한다.
- [x] Projects 카드는 Grid의 `auto-fit`, `minmax`로 반응형 배치한다.
- [x] 모바일 퍼스트로 작성하고 768px, 1024px 브레이크포인트를 사용한다.
- [x] 모바일에서 내비게이션 메뉴를 숨기고 햄버거 버튼을 표시한다.
- [ ] 버튼과 카드에 hover 효과와 transition을, 카드에 box-shadow를 적용한다.

## 3. JavaScript와 인터랙션 — PDF 4~5쪽

- [ ] `const`, `let`을 사용하고 `addEventListener`로 이벤트를 연결한다.
- [ ] `querySelector`, `querySelectorAll`, `textContent`, `innerHTML`, `classList.add/remove/toggle`을 활용한다.
- [ ] `click`, `submit`, `scroll`, `input` 이벤트를 다루고 필요한 곳에 `event.preventDefault()`를 사용한다.
- [x] 햄버거 버튼을 누를 때 `classList.toggle('active')`로 메뉴를 열고 닫는다.
- [x] 내비게이션 링크를 누르면 해당 섹션으로 부드럽게 이동한다.
- [x] 스크롤 300px 이상에서 맨 위로 이동하는 버튼을 표시하고 클릭 시 맨 위로 이동한다.
- [x] 스크롤 60px 이상에서 내비게이션 배경색을 변경한다.
- [x] 다크 모드를 토글하고 로컬스토리지에 저장해 새로고침 후에도 유지한다.
- [x] Intersection Observer로 스크롤 애니메이션을 구현한다. threshold는 0.2 이상을 권장한다.
- [x] 스크롤 기준값과 Observer threshold를 README에 명시한다. 과제에서 이 값들은 변경을 허용한다.

## 4. 문의 폼 — PDF 5쪽

- [ ] 이름, 이메일, 메시지를 입력받는다.
- [ ] 필수값과 이메일 형식을 검증하고 오류를 해당 필드 근처에 표시한다.
- [ ] 제출 시 기본 동작을 막고 검증 통과 시 성공 메시지를 표시한다.

## 5. ES6+, GitHub API와 상태 관리 — PDF 5~6쪽, 8쪽

- [ ] 화살표 함수, 템플릿 리터럴, 구조분해 할당을 활용한다.
- [ ] `map`으로 API 데이터를 HTML 카드로 변환하고 `forEach`로 배열을 순회한다.
- [ ] `fetch`와 `async/await`로 `https://api.github.com/users/{본인아이디}/repos`를 호출한다.
- [ ] 요청 중에는 스피너 또는 로딩 문구를 표시한다.
- [ ] 성공 시 저장소 카드 목록을 표시한다.
- [ ] 실패 시 오류 메시지와 재시도 버튼을 표시하고 `try/catch`로 오류를 처리한다.
- [ ] 저장소가 없으면 빈 상태 메시지를 표시한다.
- [ ] 레이트 리밋에 따른 403 응답도 오류 UI로 처리한다. PDF는 비인증 호출을 시간당 60회로 안내하므로 반복 요청에 유의한다.
- [ ] 테마, API 요청, 폼 검증 등 최소 세 가지의 상태 변경과 렌더링 흐름을 구현하고 설명할 수 있게 한다.

## 단계별 진행 순서

아래 항목은 전체 진행 순서이며 한 번의 대화에서 완료할 작업량을 뜻하지 않는다. 2단계부터 시맨틱 HTML, 앵커 링크, 외부 파일 연결처럼 개념별로 나누어 구현·검증하고 학습자료를 작성한다.

1. 요구사항과 작업 기준 정리: 이 문서를 작성하고 PDF와 대조한다.
2. HTML 뼈대와 개발 환경: 여섯 섹션, 앵커 링크, 외부 파일 연결을 만들고 Live Server에서 확인한다.
3. 반응형 CSS: 모바일부터 시작해 태블릿·데스크톱 배치와 테마 변수를 구현한다.
4. 기본 인터랙션: 메뉴, 스크롤, 테마 저장과 애니메이션을 하나씩 구현한다.
5. 폼 검증: 입력 상태와 오류·성공 메시지를 연결한다.
6. GitHub API: 로딩·성공·에러·빈 상태와 재시도를 구현한다.
7. 최종 검증과 제출 준비: 기능을 점검하고 배포, 스크린샷, README를 완성한다.
