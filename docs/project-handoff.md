# 프로젝트 이관 절차

프로젝트를 시작할 때만 읽는다. 운영 규칙의 본문은 AGENTS.md·CLAUDE.md와 각 참조 문서에서 관리한다. 이관과 지침 정리는 Codex가 담당한다.

## 이관할 파일

| 대상 | 처리 |
| --- | --- |
| AGENTS.md·CLAUDE.md | 역할별 운영 규칙을 계승하고 프로젝트 이름·과제 조건·경로를 교체한다. |
| docs/learning/GUIDE.md | 작성·검증 근거 활용 기준을 계승하고 기술별 설명 기준을 조정한다. |
| docs/tool-environment.md·config/tool-requirements.txt | 필요한 도구의 경로·사용법·복구법을 계승한다. 과거 검증 결과와 현재 설치 확인을 구분한다. |
| docs/project-handoff.md | 이 절차를 계승하고 아래 기준 기록을 새 출처로 교체한다. |
| docs/progress.md | 구조만 참고해 새 요구사항·미완료 체크리스트·현재 상태를 작성한다. |
| .gitignore | 새 기술과 산출물에 맞춰 작성한다. 테스트 디렉터리 전체 제외를 자동 계승하지 않는다. |

## 실행 순서

1. 출발·도착 프로젝트의 기존 파일과 Git 상태를 확인한다. 기존 파일을 덮어쓰거나 사용자 변경을 함께 커밋하지 않는다. Git 저장소가 없으면 그 사실을 기록한다.
2. 검토된 운영 파일만 가져온다. 소스·과제 PDF·완료 상태·학습자료 본문·이미지·배포 설정·서비스 주소·인증 정보·세션 로그는 자동 이관하지 않는다. 이전 학습자료는 필요할 때 원본 링크로 연결한다.
3. 새 과제의 기존 분석과 원문에서 기술 조건을 확인하고 지침을 조정한다. 요구사항 문서가 이미 있으면 역할을 구분하고, 구현 체크리스트와 현재 상태는 docs/progress.md에서 관리한다. 미정인 주제·기술 선택을 임의 확정하지 않는다.
4. 같은 컴퓨터에서는 공통 설치물을 재사용한다. 필요한 도구의 존재·버전·최소 동작만 확인하며, 브라우저 실행 검증 등 하지 않은 확인은 구분한다. 새 환경의 설치·복구는 필요할 때 수행한다. 권한·인증 설정은 별도 확인하며 자동 복사하지 않는다.
5. 새 프로젝트에 필요한 문서 링크와 경로, 이전 과제 조건의 잔존 여부를 확인한다. 아래 형식으로 기준 저장소·커밋·이관일을 이 문서에 한 번 기록한다. Git 저장소를 초기화할 때는 기존 사용자 파일을 초기 커밋에 임의 포함하지 않는다.

## 기준 기록과 이후 관리

새 프로젝트의 이 문서 끝에 `기준 저장소 / 기준 커밋 / 이관일`을 적는다. 기준 커밋은 이관할 운영 파일이 포함된 검토 완료 커밋으로 한다. 이관 이력을 별도 문서로 누적하지 않는다.

개선은 현재 프로젝트에서만 관리하고 다음 프로젝트가 이를 계승한다. 완료된 프로젝트에는 일괄 반영하지 않는다. 여러 프로젝트의 공통 수정이나 개선 누락이 반복되면 시작용 템플릿 도입을 검토한다. 그 전에는 별도 전역 지침 저장소·동기화 자동화를 만들지 않는다.
